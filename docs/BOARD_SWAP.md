# 替代板卡调研 —— 「逻辑资源不超过 EG4S20」的安路开发板

> 触发原因：官方平台 **HX4S20C 可能缺货**，需要找「逻辑资源 ≤ 4S20」的安路替代板。
> 日期：2026-09-29。所有结论后附来源；未证实的一律标注「未查到 / 未确认」。
> 配套原始调研（供货与规则细节、逐条来源）：`调研_HX4S20C供货与竞赛规则.md`（工作区根目录）。

## 0. 三句话结论

1. **「≤ 4S20 且能直接跑本工程」的器件实际上只有一个：EG4S20 本身**（19600 LUT，恰好等于上限）。
   本工程的帧仓 / 媒体缓存**完全建立在 EG4S20 封装内的 2M×32bit SDR SDRAM 上**
   （原语 `EG_PHY_SDRAM_2M_32` + 三个加密控制器 `sdr_as_ram` / `sdr_init_ref` / `sdr_wrrd`）。
   本机 TD 6.2.1 的 IP 目录把这条路径写成了**器件白名单**：
   `ip/depot/Catalog.xml:782` → `SDRAM` IP 只支持 `^EG4S20BG256$|^EG4S20CG324$|^EG4S20NG88$`。
2. **比 4S20 小的安路器件都没有这块片内 SDR SDRAM**：EG4A15/EG4X15（14720 LUT）、EG4A20/EG4X20、
   EF2/EF3/EF4、SF1S60（5824 LUT）、SF2S50 全部没有 SDR SDRAM 原语（它们带的是封装内 Flash / PSRAM）。
   唯一「更小且带 2M×32 SDRAM」的是 **AL3S10LG144（8640 LUT）**，但 **TD 6.2.1 根本不支持 AL3**
   （`arch/` 下无任何 AL3 器件库）→ 与锁定的工具链冲突。换这些器件 = 帧缓存要外挂存储 + 自写控制器 = 重做存储层。
3. 所以正确的问题不是「换更小的器件」，而是「**换一块同样用 EG4S20BG256 的板**」。
   此时 **RTL / 加密黑盒 / 仿真零改动**，只需**重写 `constr/pin.adc`**（外加第 4 节的三个条件项）。
   ✅ **2026-09-29：官方已给出临时许可** → 「能否换板」这条不再阻塞，可以按技术路线准备替代板
   （正式提交前建议仍保留这份许可的书面/聊天记录）。

### 2.3 资源够不够（用实测数字，不要用推算）

**本工程 route 后实测**（`build/hdmi_player/td_project/hdmi_player_Runs/phy_1/route.qor`，M3 轮）：
LUT **4959 / 19600 = 25.3%**、REG **5547 / 19600 = 28.3%**、**Slices 4731 / 9800 = 48.3%**、
RAM9K 23/64、DSP 9/29、PLL 2/4。

> ⚠️ 注意：**Slices ≠ LUT**。安路一个 PLB(slice) 的 LUT 资源与 FF 资源是分开计的，
> 本设计 4959 LUT 却占了 4731 slice，说明**布线打包效率不高（宽 mux / BRAM 周边逻辑）**，
> 不能拿 `Slices × 2` 当 LUT 用量。子调研报告 `analysis/anlogic_device_feasibility.md` 里
> 「LUT ≈ 9462（48%）」是**按 slice 推算出来的，与实测不符，以 route.qor 的 4959 为准**。

按实测比例外推（**推算，非实测**）：

| 器件 | LUT/FF | LUT 占用 | FF 占用 | slice 占用 | 结论 |
|---|---|---|---|---|---|
| EG4S20（当前） | 19600 | 25.3% | 28.3% | 48.3% | ✅ 有余量 |
| EG4A15 / EG4X15 | 14720 | ~34% | ~38% | ~64% | 逻辑装得下，**但无片内 SDRAM** → 仍不可行 |

→ **结论不变**：卡住替代方案的不是逻辑资源（EG4A15 都装得下），而是**封装内那块 2M×32 SDR SDRAM**。

### 2.4 加密 IP 的复用边界（哪些能带走、哪些带不走）

- **`sdr_as_ram` / `sdr_init_ref` / `sdr_wrrd`（SDRAM 控制器）**：**带不走**。
  它们要配 `EG_PHY_SDRAM_2M_32`，而 TD 6.2.1 的 `SDRAM` IP 白名单只有 EG4S20 三个封装（§2.2），
  EG4D20 是另一套 `DDR SDRAM` IP → **只在 EG4S20 上可用**。
- **`hdmi_1_4b_transmitter_core_wrapper`（HDMI 核）**：**同族（EG4）内复用有可能，但未证实**。
  可查到的官方说法只有安路的技术文章《[安路 FPGA 实现 HDMI 的编解码的视频显示方案](https://www.anlogic.com/news/company-news/45.html)》
  一句 *"该方案已经在 EG4 等多款安路芯片上成功实现"* —— 那说的是**方案（源码级参考设计）**，
  **不等于我们手上的加密黑盒能跨型号复用**。跨族（EF/SF/PH1）几乎肯定要重新向 FAE 索取。
- 因此：**换 EG4S20 的另一块板 = 两个黑盒都能带走；换任何别的器件 = 至少丢掉存储黑盒。**

### 2.5 两个必须知道的下单陷阱

- **`EG4S20BG256B` 的疑点**：安路官网 EG4 选型表里 `EG4S20BG256B` 那一行的 **DDR/SDRAM 栏是空的**，
  只有 `EG4S20CG324` 写了 `2M*32`。而 TD 6.2.1 的器件表里**根本没有 `EG4S20BG256B` 这个器件名**
  （只有 `EG4S20BG256`，且带 64Mb SDR SDRAM）。Sipeed / 米联客 / SparkRoad / 安路官方 MINI-DEV 页
  都明说 EG4S20 合封 2M×32 SDRAM。→ **下单前逐字确认料号/丝印是带片内 SDRAM 的那一版**，
  这是全场最容易翻车的点（买错 = 帧缓存与整套加密 SDRAM 控制器同时作废）。
- **芯片也缺**：立创商城 EG4S20BG256（编号 C2762849，FBGA-256 17×17）页面写明
  *"参考售价为 0 元起，**现货库存数量 0 个**"*；云汉芯城只有 **NG88**（不是 BG256）。
  → 缺货是**整条供应**的现象，优先走官方/代理。

### 3.1 「大拇指」EG4S20 核心板 + M0 底板：引脚映射（已查到，语雀 markdown 导出）

资料出处：核心板 [口袋实验知识库](http://kb.koudaishiyan.com/7001.html)（DMZ_Anlogic，2021）、
底板（M0 底板）[语雀 · 微处理器原理与片上系统设计](https://www.yuque.com/yingmuketang/01/ybuzk6rfe3lk923i)（2024 版）。

**HDMI 怎么走的 —— 这是关键结论**：底板的 HDMI 是 **FPGA 直接输出 TMDS 差分对**，
引脚表里只有四个信号、**中间没有任何 HDMI 发送芯片**（TFP410 / ADV7511 / SiI9022 之类）：

| 底板引脚 | 功能 |
|---|---|
| **P1** | HDMI_CLK_P |
| **N1** | HDMI_D0_P |
| **P4** | HDMI_D1_P |
| **J3** | HDMI_D2_P |

→ **和 HX4S20C 是同一套做法（LVDS33 直出 TMDS）**，所以
**`hdmi_1_4b_transmitter_core_wrapper.enc.v` 与 `hdmi_phy_warpper.v` 可以原样复用，只需改这 4 个引脚号**。
HDMI 音频本来就是从核内部走的（不占板级引脚）→ 音频链路同样不用改。

**我们 28 个信号在新板上的映射**（`—` = 引脚表里没有，需原理图确认）：

| 我们的信号 | HX4S20C | 大拇指（核心板 + M0 底板） | 备注 |
|---|---|---|---|
| `clk` | R7 | **R7** | **完全一致、50 MHz** → `sys_pll` / `video_pll` 不用重生成 |
| `rst_n` | A2（独立按键） | **A9**（= 拨码 SW0） | **厂家教程 KB 7002 给出的 `.adc` 示例就是 `RSTn → A9`**，照抄即可（本板无专用复位键） |
| `key1` / `key2` | B2 / C1（独立按键） | **独立按键 E3** + 4×4 矩阵键盘（`Key_Col[3:0]`=F10,C11,D11,E11 输出扫描、`Key_Row[3:0]`=D9,F9,C10,E10 输入读回）；另有 8 路拨码 `SW_In[7:0]`=A9,A10,B10,A11,A12,B12,A13,A14 | 推荐 **key1=E3（独立按键，直接可用）**、key2=矩阵里的一个键（最小实现：col[0] 拉低、col[3:1] 拉高、读 row[0]） |
| `HDMI_CLK_P` | C3 | **P1** | LVDS33 |
| `HDMI_D0_P` | G5 | **N1** | LVDS33 |
| `HDMI_D1_P` | F1 | **P4** | LVDS33 |
| `HDMI_D2_P` | E1 | **J3** | LVDS33 |
| `HDMI_DDC_SCL` / `SDA` | P2 / R2 | **—（底板 HDMI 段只列了 4 对差分）** | ⚠ 很可能没接到 FPGA；见 §3.2 |
| `sd_ncs` | A12 | **F13** | 底板 SD 卡槽是 **SPI 模式** |
| `sd_dclk` | A14 | **F15** | |
| `sd_mosi` | A13 | **F14** | |
| `sd_miso` | B14 | **D14** | 注意 B14 在这块板上是 LED0 |
| `seg_data[7:0]` | C15 C16 B6 A5 B5 A8 A7 A6 | `Digitron_Out[7:0]` = A4,A6,B8,E8,A7,B5,A8,C8 | ⚠ **极性相反**：核心板段选**高**有效（共阴），我们是低有效 |
| `seg_sel[5:0]` | E12 E10 C13 F10 E11 D11 | `DigitronCS_Out[3:0]` = C9,B6,A5,A3 | ⚠ 只有 **4 位**（我们**是 6 位**，`seg_display` 里写死 `scan_idx==5`）→ `seg_sel` 缩到 `[3:0]`；位选低有效一致，扫描顺序也不用换（两边第 0 位都是最右一位） |

> **矩阵键盘的驱动方式（KB 原文）**：`Key_Col[3:0]` 是 4 个**输出**、`Key_Row[3:0]` 是 4 个**输入**。
> 一次把一列拉低、其余拉高，再读 4 行：某行为低 = 该行该列的键被按下
> （原文例子：`KEY1` 拉低、`KEY2~KEY4` 拉高，按 `KEY15` → `KEY5` 读到低）。
> 行输入需要上拉，`constr/pin_damuzhi.adc` 里已按 `PULLTYPE = PULLUP` 写。
>
> **已产出可直接用的引脚草案**：[`constr/pin_damuzhi.adc`](constr/pin_damuzhi.adc)

### 3.1.1 与官方 HX4S20C 的差异对照（结论：核心链路几乎无差别，但作为**参赛平台**差别不小）

**完全相同（这部分可以直接复用，零改动）**：
EG4S20BG256 器件（19600 LUT/FF、片内 2M×32 SDR SDRAM、4 PLL、16 全局时钟、8 通道片内 ADC）·

- **"跑得起来吗"** —— 能，而且核心链路（HDMI/SDRAM/SD/音频）几乎不用改，只换引脚约束；
- **"等价替代吗"** —— 不等价。它是**同一颗芯片的另一个平台**，差距不在算力和 HDMI，

### 3.1.3 实现差异清单（HX4S20C → 大拇指 核心板 + M0 底板）

**零改动（占绝大多数）**：器件与封装（`prj/prj.json` 的 `deviceChip` / `package` 一字不改）、
`constr/timing.sdc`、两颗 PLL（输入同为 50 MHz，`.FIN("50.000000")` 不用动）、
加密 HDMI 核 + `hdmi_phy_warpper`、三个加密 SDRAM 控制器、`src/rtl/**` 主体、
`sim/` 下 7 个 testbench、SD 驱动。

**要改的只有 4 项，全是小改**：

| # | 项 | HX4S20C | 大拇指（M0 底板） | 具体改动 |
|---|---|---|---|---|
| 1 | 引脚约束 | `constr/pin.adc` | `constr/pin_damuzhi.adc`（**已产出**） | 28 个信号重写；`prj/prj.json` 的 `adc` 指过去即可。**纯约束，不动 RTL** |
| 2 | 数码管 | 板上 8 位，我们驱动 **6 位**、段选**低**有效 | 板上 **4 位**、段选**高**有效 | `seg_display` 参数化 `DIGITS` / 段选极性（~10 行）。**但 24 bit 状态字塞不进 4 位** → 要么只显示 4 个最有用的半字节，要么两页轮流刷 —— 这是设计决策，不只是接线 |
| 3 | 按键 | 2 个**独立按键** key1/key2 → 短按+长按共 4 种功能 | **1 个独立按键 E3** + 4×4 矩阵键盘 | key1 = E3，**直接复用现成的 `key_debounce`**；key2 走矩阵（最小方案几行 RTL，或写 4×4 扫描拿 16 个键）。top 需加 `key_col[3:0]`（输出）+ `key_row[3:0]`（输入） |
| 4 | HDMI DDC/EDID | P2/R2 有约束，核的 DDC 直连顶层 | 引脚表未列 → **大概率没接** | 删 `HDMI_DDC_SCL/SDA` 两个端口 + 2 行约束，再**实测无 EDID 时能否出图** |

**唯一可能"翻车"的是第 4 项**（其余三项纯 RTL/约束，仿真阶段就能验完）。
若加密核读不到 EDID 就不出图，退路：① 从底板其他 IO 找 DDC（要原理图）；② 用扩展排针外接一路
I²C 补到显示器 DDC。

**工作量估计**：约束 ~0.5 h（草案已产出）· 数码管 0.5–1 h · 按键 0.5 h · DDC 改动 15 min + 上板 1 次

### 3.2 硬木这块的 HDMI 还要额外做的两件事（唯一的不确定点）

1. **DDC / EDID 通路要确认**。底板 HDMI 段只列了 4 对 TMDS，**没有 DDC 的 SCL/SDA**。
   我们的 `src/rtl/top.v:591-592` 是把加密核的 `O_ddc_scl` / `IO_ddc_sda` **直接引到顶层端口**
   （`HDMI_DDC_SCL` / `HDMI_DDC_SDA`），所以处理方式二选一：
   - 原理图确认 DDC 接到了某两个 IO → 照常约束；
   - 确认没接 → **删掉这两个端口 + `pin.adc` 两行**（源码里就这两处），
     再**实测加密核在"读不到 EDID"时是否仍然出图**。这是换板后第一个要验证的点。
2. **数码管要改三处**：位数 8→4（`seg_sel[5:0]` → `[3:0]`）、段选极性取反、位选映射到 `DigitronCS_Out`。
   若暂时不想动 RTL，也可以**先不接数码管**，诊断改看 LED（核心板有 8 个 LED）。

> ℹ️ 方法记录：语雀页面是 JS 渲染、`web_fetch` 抓不到正文，但
> `https://www.yuque.com/<空间>/<文档slug>/markdown?plain=true&linebreak=false&anchor=false`
> 能直接拿到 markdown 正文（本次整张底板引脚表就是这么拿到的）。以后查这批板卡资料可直接用。

**屏幕怎么接（SANC G73）**：G73 是 27" 2K 240Hz 电竞屏，接口为 **2×HDMI + 2×DP + 1×3.5mm 音频口**
（公开参数未见内置扬声器）。
- **接法**：底板那个 **HDMI 输出座**（走 P1/N1/P4/J3）→ 标准 HDMI 线 → G73 的**任意一个 HDMI 口**。
  输出座只有一个（不像 HX4S20C 有 A/B 两个），不存在选错口的问题。
- **音频**：把耳机/有源音箱插到 **显示器背面的 3.5mm 音频输出口**（HDMI 里传来的音频从那里出）。
  注意显示器 OSD 里若音量默认为 0/静音要调起来 —— 这就是赛题「HDMI 音频终端能出声」的验收路径。
- **分辨率**：我们输出 **640×480@60**（TMDS 250 Mbps）。G73 这类高刷屏的 HDMI 口一般仍接受 480p60
  （CEA-861 把 640×480p 列为 HDMI sink 的基础格式），但**高刷屏有时只在高分辨率下工作** ——
  若黑屏/报"不支持该分辨率"，退路是改跑 **720p**（计划里的可选加分项：像素时钟 74.25 MHz、
  串行 371.25 MHz，EG4 的 LVDS 上限 800 Mbps 够用）。
- **不要用**：底板的 VGA（RGB565 + HS/VS）和并口 LCD FPC —— 赛题要求 HDMI 音视频，VGA 不算且无音频通路；
  板载 3.5mm（F3 `Audio_PWM`）只能当**调试手段**（先确认合成器在响），不能替代 HDMI 音频。
- **线**：赛题要求 HDMI 1.4+ 纯铜线、≤5 m；480p 只跑 250 Mbps，随便一根合格 HDMI 线都够。

**必改**
- `constr/pin.adc` —— 现有 **28 个信号**的引脚号必须**按新板原理图逐个重写**：
  `clk / rst_n / key1 / key2`（4）、`HDMI_CLK_P / D0_P / D1_P / D2_P`（4）、`HDMI_DDC_SCL / SDA`（2）、
  `sd_ncs / dclk / mosi / miso`（4）、`seg_data[7:0]`（8）、`seg_sel[5:0]`（6）。
  **纪律不变：不许臆造引脚号。**

**条件改**
- **晶振频率**：`src/vendor/pll/sys_pll.v`、`video_pll.v` 输入写死 `.FIN("50.000000")`。
  新板若为 24/25 MHz，必须**用 TD 6.2.1 重新生成这两个 PLL IP**（不能用更高版本 TD）。
- **数码管**：位数或极性不匹配时（大拇指板是 4 位 + 段选高有效），把 `seg_display` 参数化，
  或把诊断状态字改输出到 LED / 直接裁掉 `seg_*` 端口。
- **下载器**：新板无板载下载器时需外置 AL-LINK / JN-LINK（额外成本）。

**不用改**
- `src/rtl/**` 全部 RTL、`src/vendor/mem/**` 与 `src/vendor/hdmi/**` 加密黑盒、片内 SDRAM 数据通路、
  `sim/` 下 7 个 testbench、`constr/timing.sdc`。

**验证顺序**
1. `node tools/td_build.mjs` 重跑 → 看 `route.qor`：Setup/Hold WNS ≥ 0、0 违例端点、Slices 与当前 48.28% 相当。
2. 先烧**只跑内建测试图 + 音频**的版本，确认 HDMI 出图 + 耳机出声。
3. 再看诊断位：`SD就绪`、`找到张数 ≥ 4`，然后才接 TF 卡跑完整链路。
